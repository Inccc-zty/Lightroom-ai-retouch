# 调参顺序

技术流程管的是「怎么连、怎么验」；这份管的是「先动哪个滑块」。

**顺序不能乱，因为每一步都会改变后面判断的依据。**
先调色再定明暗，明暗一变色彩关系全变，等于返工。

## 总原则

**从「影响全局的」到「影响局部的」，从「粗」到「细」。**

排在前面的一改，后面全部重算；排在后面的一改，前面不受影响。
所以永远先动那个「一动就全变」的参数。

## 九步顺序

### 第 0 步：看画面，定基准（不动参数）

- 光从哪来（受光面朝向、影子方向、最暖的地面带）
- 主体是什么、在哪
- 什么时段（决定色温记忆值）
- 原片最大的错是什么（灰 / 暗 / 过曝 / 偏色）

**这一步不产生任何参数，但决定后面所有判断。** 跳过它，后面全是机械操作。

### 第 1 步：相机配置文件 `CameraProfile`（**最先做，不许跳**）

配置文件是整条渲染链的**基础映射**，它决定了 RAW 数据怎么变成颜色。
后面所有滑块都是在它之上工作——**选错了，HSL 怎么调都补不回来**。

#### 题材 → 配置文件对照表

| 题材 | 用什么 | 理由 |
| --- | --- | --- |
| **动物 / 生态 / 昆虫 / 植物（绿色为主）** | **`Camera Standard`** | 绿色纯、饱和够、不发黄 |
| 风光（需要更大动态和层次） | `Adobe Landscape` 或 `Camera Standard` | Landscape 会强化暖色和对比，看片子 |
| 人像 | `Camera Portrait` 或 `Camera Standard` | Portrait 肤色更柔 |
| 需要最平起点做重度后期 | `Camera Flat` / `Adobe Flat` | 但绿色会明显变灰，慎用 |
| **`Adobe Standard`（动物/植物题材）** | **不要用** | 见下方实测 |

#### 实测：Adobe Standard 对绿色的破坏（ZTY_6198，同参数只换配置文件）

| 区域 | 指标 | Camera Standard | Adobe Standard | 差值 |
| --- | --- | --- | --- | --- |
| 苔藓 | G−(R+B)/2 | 53.0 | 37.2 | **−15.8** |
| 苔藓 | R−B | +11.6 | **+46.5** | **+34.9** |
| 苔藓 | 饱和度 | 0.905 | 0.711 | **−0.194** |
| 苔藓 | 亮度 | 68.1 | 78.9 | +10.9 |
| 苔藓（下方） | 饱和度 | 0.895 | 0.664 | −0.231 |
| 森林背景 | G−(R+B)/2 | 41.7 | 22.9 | **−18.8** |
| 森林背景 | 饱和度 | 0.733 | 0.468 | **−0.265** |
| 蛇身 | G−(R+B)/2 | 58.0 | 40.2 | −17.9 |
| 蛇身 | 饱和度 | 0.787 | 0.593 | −0.193 |

**三个方向同时坏掉：**

1. **绿变淡**：G−(R+B)/2 掉 15–19，绿色分量被削弱
2. **绿变黄**：R−B 涨 33–35，红相对升高，翠绿往黄绿/土黄跑
3. **绿变灰**：饱和度掉 0.19–0.27，同时亮度涨 7–12

合起来就是"灰扑扑的黄绿"，苔藓和树叶最明显。

**这不是后期能补救的**：把 HSL 绿通道饱和度拉满，得到的是"过饱和的灰黄绿"，
不是 Camera Standard 那种带青的翠绿。基础映射错了，后面全是补偿。

#### 写入方式

```bash
python scripts/lr_bridge.py develop-set --path "<照片>" --set "CameraProfile=Camera Standard"
```

- 用**纯名称**，带不带 `Group: ` 前缀都行，LR 会规范化
- **必须带 `--path`**
- 写完 dump 回读确认，名字不对说明拼错了（LR 会静默丢弃不存在的名字）

#### 决策记录要求

这一步必须**在报告里明确写出**：当前是什么、该用什么、为什么不动或为什么改。
只"看了一眼没动"不算做过这一步。

### 第 2 步：曝光 `Exposure2012`

**为什么第二个**：曝光决定直方图整体位置。后面所有明暗操作都站在这个位置上，
位置错了，黑白场、曲线、阴影高光全要重算。

**判断依据：看中位亮度，不看光影。**

| 中位亮度 | 判断 |
| --- | --- |
| < 45 | 偏暗，先提曝光再说其他 |
| 45–70 | 正常区间，风光片大多数在这 |
| > 75 | 偏亮，检查是不是整体过曝 |

辅助看全图平均亮度：风光片通常落在 75–100。

**注意**：这一步只看「整体位置对不对」，不看局部。局部的明暗是第 8 步的事。

### 第 3 步：白平衡 —— 参考物比公式重要

### 做，不许跳

这一步最容易被"看起来还行"糊过去。必须**明确写出**改没改、依据是什么。
如果结论是"不动"，也要说清为什么不动（例如：原片值落在场景先验区间内）。

### 参考物三不准

| 不能当参考 | 原因 |
| --- | --- |
| **水面 / 玻璃 / 镜面** | 反射天空就偏蓝、反射树叶就偏绿。实测：一张蛇片的水面 R−B 为 −10，按它推要 5686K，实际把整片绿推黄了 |
| **主体本身** | 绿蛇、红叶、黄羽毛，饱和度本来就高；它的"低饱和像素"其实是它自己的高光 |
| **天空** | 本来就是蓝的 |

可靠参考：**非反射的灰/白表面** —— 灰石、水泥路、枯木的灰白面、白墙、云的主体。

### 工具：`scripts/auto_wb.py`

```bash
python scripts/auto_wb.py photo.jpg --temp 5106 --tint 11          # 自动找候选
python scripts/auto_wb.py photo.jpg --ref 0.62,0.28,0.72,0.34      # 指定参考区
python scripts/auto_wb.py photo.jpg --scene forest                 # 场景先验
```

输出三个数：

- `R−B` 蓝黄轴，±5 以内可接受
- `G−(R+B)/2` 绿品红轴，±6 以内可接受
- `饱和度` **< 0.15 才可信；0.15–0.22 参考性弱、只取一半修正量；> 0.22 直接作废**

标定过的斜率（Nikon NEF / Adobe 引擎 / 5000K 附近）：**R−B 每 +1 需要 +57.5 K**。

### 当全图都没有中性物时

森林、草原、大面积植被的片子经常如此。工具会直接报 `可信度: no`，此时**不要用像素统计**，
改用场景先验：

| 场景 | Temperature | Tint |
| --- | --- | --- |
| 晴天正午直射 | 5500–6000 | 5–8 |
| 阴天 / 开阔阴影 | 6000–6800 | 5–10 |
| **林下散射（树冠过滤）** | **5000–5600** | **8–16** |
| 日出日落前后 | 3200–4500 | 5–15 |
| 蓝调时刻 | 7000–10000 | 0–10 |
| 室内钨丝灯 | 2800–3200 | 0–8 |

拿到先验区间后，**用视觉确认一次**：苔藓/叶片是不是翠的，有没有发黄或发紫。

### 一条血的教训

一张绿蛇片，用户手动把色温从 5000 调到 5106。我用"水面 R−B = −10 偏冷"的数据，
把它推到 5300，结果整片苔藓从翠绿变黄绿，用户当场看出问题。

正确结论是：**5106 / Tint 11 落在林下散射先验区间内，用户是对的**。
水面那个 −10 是反射天空造成的，不是白平衡偏冷。

**数据是用来验证判断的，不是用来替代判断的。参考物选错，算得越准错得越远。**

### 只允许一处降温

多层叠加降温是高频事故：背景层 `temp −4` + 加雾层 `temp −9` → 水面直接发蓝。
**全片只在一个地方动 Temperature**，其余层不碰。


### 第 4 步：黑白场 `Whites2012` / `Blacks2012`

**先测原片的两端，再决定动不动。**

```bash
python scripts/qc.py orig.jpg     # 看 p99 与死黑占比
```

| 原片状态 | 该怎么做 |
| --- | --- |
| 死黑 < 3%、p99 235–245 | 微调，各 ±10 以内 |
| **死黑 > 5%** | **不要压黑场**，反而要抬（Blacks 往正走） |
| p99 > 250 | 先压白场，别加对比 |

实测反例：一张片原片死黑已 5.83%，照搬同场景另一张的 `Blacks −12`，
死黑直接推到 **11.09%**，画面塌了。

**同场景的两张照片不能互相套参数**，每张先测。

### 第 5 步：高光 / 阴影 `Highlights2012` / `Shadows2012`

这是**全局**的活，别用蒙版模拟。

- 高光：压下去让云层/亮面有厚度。**接近高光的区域压不动**（已经 145 的再加 EV 只出 +1.4）
- 阴影：抬起暗部细节，但**别抬到发灰**。判据看中位亮度，不看单点

判据：调完后画面应该"亮的地方还亮，暗的地方还有东西"，不是"整体变亮"。

### 第 6 步：对比 / 曲线 `Contrast2012` / `ToneCurvePV2012`

**曲线优先于对比滑块**，因为它能精确控制哪个亮度区间加对比。

缓 S 曲线（最常用）：
```
0,0   32,33   96,100   168,172   255,255
```
- 暗部 32 抬到 33（保护暗部不压死）
- 中间 96→100（加一点）
- 亮部 168→172（压一点）

**判据**：加完对比，中位亮度不能掉超过 8%，死黑不能涨超过 1 个百分点。

用户的反馈"对比度太高"通常指两件事：整体 Contrast 太大，或者暗部被压死。
先降 Contrast，再看死黑。

### 第 7 步：色彩 `HSL` / `Vibrance` / `Saturation`

一次只动一个通道。判据是**色相自然度**，不是数值大小。

偏色定位方法：把可疑色相涂色叠加到图上，一眼看出偏色来自哪个物体。
不要用全图 RGB 均值判断"是不是太红"——RGB 只能定位"红在哪里"。

**禁止**在这里顺手改主体色相。用户要光影就只做光影，改色属于越界。

### 第 8 步：蒙版光影塑形

**这一步之前有一道硬门槛，见下方「第 8 步的三条门槛」。**

分层模板见 `light-sculpting.md`，蒙版类型选择见 `mask-selection.md`，
布尔运算（主体 ∩ 局部）见 `mask-selection.md` 的布尔章节。

### 第 9 步：细节 `Texture` / `Clarity` / 锐化

放在最后，因为锐化会放大前面所有的问题（噪点、蒙版接缝、色阶断层）。

- `Texture` 只影响中高频细节，相对安全
- `Clarity` 影响中间调对比，**加多了会让画面发硬、金属感**
- 主体上给 `clarity 10–15 + texture 10–12` 足够；超过 22 容易假

## 第 8 步的三条门槛

写第一个蒙版之前，做一次**只有全局参数**的导出（关掉全部蒙版），逐条回答：

1. 全图亮度、中位、死黑、p99 是否都在目标区间？
2. 纵向/横向亮度梯度是否合理，无断层、无大片发灰？
3. 画面是不是「调好了，但还平」—— 问题只剩「缺体积」，而不是「缺对比 / 缺通透」？

**三条全 yes 才允许动蒙版。** 任何一条 no，回第 2 步。

并且**不允许在同一条命令里既改全局又写蒙版**。

## 全局改动要克制

如果原片是摄影师/用户自己调过的，**它可能已经是好的基调**。

实测：一张绿蛇片，原片参数 `Exposure 0.67 / Contrast 0 / H −35 / S 10 / Tint 19`。
我按标准流程改到 `Exposure 0.88 / Contrast 7 / 曲线 S 形`，结果画面发灰发闷，
反而不如原片通透。

**正确做法**：先判断原片基调对不对。对的话，全局只做微调（±0.05 EV、Contrast ±3），
把力气全花在第 8 步的蒙版塑形上。

判据：把原片和当前版并排看，如果原片更"透"，说明全局改坏了，退回去。

## 一张速查表

| 步 | 参数 | 判断依据 | 不属于这里的东西 |
| --- | --- | --- | --- |
| 0 | — | 光向、主体、时段 | 所有参数 |
| 1 | CameraProfile | 原片是否发灰 + 当前配置 | 对比度滑块 |
| 2 | Exposure | **中位亮度** | 局部明暗 |
| 3 | Temperature / Tint | **中性物 + 光色记忆** | 光影（只用来排除干扰） |
| 4 | Whites / Blacks | **直方图两端** | 曲线 |
| 5 | Highlights / Shadows | 分区测量 | 蒙版 |
| 6 | Contrast / 曲线 | 层次梯度 | 色彩 |
| 7 | HSL / Vibrance | 色相自然度、偏色定位 | 明暗 |
| 8 | 蒙版 | 光向、地形、主体 | 全局基调 |
| 9 | Texture / Clarity / 锐化 | 噪点与接缝 | 前面所有 |

## 会返工的错误顺序

| 错误做法 | 后果 |
| --- | --- |
| 先调色再定明暗 | 明暗一变，色彩关系全变，白调 |
| 先做蒙版再改全局 | 全局一动，所有蒙版力度失效 |
| 一条命令里既改全局又写蒙版 | 两层改动混在一起，出问题无法归因 |
| 先锐化再看看 | 噪点和接缝被放大，只能回退 |
| 一次改 6 个参数再导出 | 出问题无法归因，不知道是哪一步 |
| 拿夕阳直射的石头判白平衡 | 全局偏暖，背光面全黄 |
| 照搬上一张的黑白场 | 同场景也会翻车（9668 死黑 5.83%，压黑场直接到 11%） |

## 和「一步一验」的关系

顺序管**先动哪个**，一步一验管**一次动几个**。

两者一起用：按九步顺序走，每一步内部可以一次改 2–3 个同族参数（比如
Whites 和 Blacks 一起定两端），但跨步骤绝不合并——第 4 步没验完不许进第 5 步。
