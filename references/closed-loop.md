# 闭环验证

## 为什么需要闭环

开环修图的失败模式是固定的：改五步，导出，发现整体偏了，但不知道是哪一步偏的，
只能全部回滚重来。

闭环把每一步都变成可验证的实验：
**写目标 → 执行 → 导出 → 测量 → 判定 → 保留或回撤**。

## 单步增量阈值

| 指标 | 安全区 | 警戒 | 处理 |
| --- | --- | --- | --- |
| 整体感知亮度变化 | < 8% | > 15% | 立即回撤一半 |
| 饱和度变化 | < 0.05 | > 0.10 | 回撤 |
| 死黑像素（L < 8）占比 | < 3% | > 5% | 抬 Shadows 或 Blacks |
| 高光溢出（L > 250）占比 | < 0.5% | > 1% | 压 Highlights 或 Whites |
| 单层 EV 绝对值 | < 0.3 | > 0.6 | 拆成两层 |

**超过警戒线就是推过头了**，不要用「但是看起来更好」说服自己。
先回撤，再换方向。

## 导出验证的硬规矩

1. **写入后等 2–3 秒再导出**。`develop_set` 返回 ok 只代表 LR 收到设置，
   渲染管线可能还没刷新，会导到中间状态
2. **关键节点双尺寸交叉验证**。2400px 和 4000px 各导一次，
   同一区域的亮度差应 < 3。差得多说明缩放算法有影响，测量结论不可靠
3. **对比图必须同源**。用同一张原片、同一缩放算法重采样，否则差异来自插值不是修图

## 三级体检

### 一级：常规体检 `qc.py`

```bash
python scripts/qc.py output.jpg
```

12 项阈值，一次性 PASS/FAIL。看这几项：

```
上/中/下       三段平均感知亮度
p1 / p99       最暗/最亮分位，判断有没有溢出
暗/白占比      暗部比例、高光溢出比例
绿S/蓝S/均S    分色饱和，判断偏色
中/前          中景÷前景 亮度比
天/中          天空÷中景 亮度比
```

**比值的分子永远是更亮那一方。** 搞反会得出荒谬的目标
（比如认为天空该比远山暗，然后把远山提亮到发光）。

### 二级：立体感体检 `depth_qc.py`

```bash
python scripts/depth_qc.py output.jpg
```

三个维度：
1. **层级梯度**：远→中→近的亮度走向是否单调、是否有断层
2. **归一化 CV**（低频-形状明暗）：`σ/mean`，衡量大块面上的明暗变化
3. **大气透视三要素**：远亮/近暗、远冷/近暖、远低对比/近高对比

**带通尺度必须按图像宽度归一化。** 60–240px 的带通在 1600px 图上占画面 3.75%–15%，
在 4000px 图上只占 1.5%–6%，同一特征会落进不同频段，数据完全不可比：

```python
def band_cv(r, s1, s2, width):
    scale = width / 1600.0
    return measure(r, s1 * scale, s2 * scale)
```

**局限**：`depth_qc` 只查「后期有没有做错」，不查「地形本身好不好」。
低频 CV 主要由地形决定（梯田绿坡 vs 平坦石滩），后期改不动。
硬追这个指标只能靠伪造明暗块，试过，更假。

### 三级：视觉判断

前两级是护栏，这一级才是裁判。

操作：
1. 裁局部（左坡、前景、远山、天空各一块），放大到 100%
2. 与原片对应区域并排
3. 问具体问题，不问「好不好看」：
   - 石头的受光面和背光面区分明显吗？
   - 有没有不自然的亮斑、光晕、蒙版接缝？
   - 暗部还能看到纹理，还是糊成一片？
   - 这块比周围亮，是因为受光，还是因为被我提亮了？

## 测量脚本骨架

```python
from PIL import Image
import numpy as np

def lum(a):
    a = a.astype(np.float32)
    return 0.2126 * a[..., 0] + 0.7152 * a[..., 1] + 0.0722 * a[..., 2]

im = Image.open(path).convert("RGB")
W, H = im.size

def region(box):
    x1, y1, x2, y2 = box
    a = np.asarray(im.crop((int(x1*W), int(y1*H), int(x2*W), int(y2*H))))
    L = lum(a)
    return L.mean(), L.std(), L.std() / L.mean()
```

区域坐标用 0–1 归一化，换尺寸不用改代码。

## 体检器的适用边界（血泪教训）

`qc.py` 和 `depth_qc.py` 的阈值是为**风光片**设计的。
直接套在微距 / 生态 / 人像片上会**全线 FAIL**，但那不代表照片差。

| 指标 | 阈值 | 为什么微距不适用 |
| --- | --- | --- |
| 平均饱和 | < 0.45 | 绿色苔藓/叶片本身 0.7+ |
| 天空/中景 | > 1.5 | 微距片没有天空 |
| 大气透视（远亮近暗） | 必查 | 微距没有远近层次 |
| 总落差 | > 70 | 暗调林下片天然低 |
| 中暗带占比 | > 12% | 大面积主体+背景同色，自然偏低 |

实测一张翠绿蛇的微距片：

```
qc.py:    平均S 0.72 > 0.45  ✗   暗部<60% 78.21 > 45  ✗   天空/中景 0.82 < 1.5  ✗
depth_qc: 总落差 0 < 70  ✗   大气透视错  ✗   p99 156 < 232  ✗
```

看上去一无是处。但对比原片：平均 S 原片 0.74、定稿 0.72（**已经降了**），
暗部占比原片 98.6%、定稿 97.5%（**也改善了**）。
FAIL 的项全部是题材特性，不是修图错误。

### 规矩

- **风光片** → qc / depth_qc 全套照跑
- **微距 / 生态 / 人像** → 只用「硬伤检查」那几项：
  高光溢出、死黑占比、色阶断层、蒙版接缝。
  比值类（天/中、中/前、大气透视、总落差）**全部不适用**
- **好看与否只能靠眼睛**，体检器在非风光题材上只是防硬伤的工具

### 更危险的是反向误判

不能因为体检 FAIL 就去「修」那些本来正确的特征。
曾经为了让「暗部 < 45%」达标去提亮暗部，结果把微距片的氛围提没了。
**指标不适用时，达标本身就是错的。**

## 记录每一次实验

每次改动都存一份 dump + 一张导出图 + 一行结论：

```
14:41  Shadows 45→28, Blacks −4→−12   结果：全图 98.4→90.8，死黑 2.09%→4.38%  判定：过头，回撤
14:46  Shadows 28→35, Blacks −12→−9   结果：全图 93.8，死黑 3.27%             判定：保留
```

没有这份记录，三天后你就不记得哪一版是哪一版，用户问「和上个版本差在哪」
只能凭记忆瞎猜——而记忆通常是错的。

## 回滚

任何时候都能回到上一版：

```bash
python scripts/lr_bridge.py tree-set --path "<照片>" --json backup.json
```

`mask_append.py` 每次写入前自动备份现有层。全局参数改动前也应该先 dump 一份全量。

**不要在没备份的情况下改 `CameraProfile`**，这是唯一一个改错了会让整张片子基调变掉、
且不容易凭肉眼还原的参数。
