# 蒙版类型怎么选

选错蒙版类型，后面参数再准也是白搭。这份文档专门治「习惯性只用径向椭圆」这个毛病。

## 四种蒙版

| 类型 | `What` | 几何字段 | 边界形状 |
| --- | --- | --- | --- |
| 线性渐变 | `Mask/Gradient` | `ZeroX/Y` → `FullX/Y` | 直线，贯穿全画面 |
| 径向渐变 | `Mask/CircularGradient` | `Left/Top/Right/Bottom` + `Angle/Feather/Roundness` | 椭圆 |
| AI 天空 | `Mask/Image` + `MaskSubType=2` | 无（LR 自己算位图） | 贴着山脊、树冠 |
| AI 主体 | `Mask/Image` + `MaskSubType=1` | 无 | 贴着人物/动物/物体 |

## 选择判据

| 你要做的事 | 该用 | 为什么 |
| --- | --- | --- |
| 整片天空压暗 / 加暖 / 调色 | **AI 天空** | 边界紧贴山脊树冠，不误伤坡顶；手画永远对不上 |
| 天空的某一块（云层亮部、地平线霞光） | 线性或径向 | AI 天空是整片，做不了"只暖一角" |
| 前景压暗 / 暗框 / 上下渐变 | **线性** | 从上到下的连续过渡，线性最自然，没有圆弧痕迹 |
| 单块石头 / 一棵树 / 一处水面 | 径向 | 局部，四边可控 |
| 沿地形走向的光带 | 径向多个串联 | 线性会贯穿全画面，误伤另一侧 |
| 人物 / 动物 / 主体抠出 | AI 主体 | 同上 |

**一句话：整片的用 AI，渐变的用线性，局部的用径向，主体的一部分用布尔（主体 ∩ 框）。**

## 我在这件事上犯过的错

### 错一：天空用径向椭圆凑合

给天空加暖，用 `lt=(-0.10,0.02) rb=(0.50,0.36)` 的椭圆。
椭圆边界是圆的，和山脊线对不上，暖色溢到了坡顶。

实测对照（同一张照片，只换层 7 的蒙版类型）：

| 区域 | 径向版 | AI 天空版 | 说明 |
| --- | --- | --- | --- |
| 纯天空 | 基准 | −1.0 | 正常作用 |
| 山脊上方天空 | 基准 | +0.6 | 正常作用 |
| 坡顶受光 | 基准 | +0.5 | **径向版在这里有污染** |
| 坡面中 | 基准 | +0.4 | 径向版轻微污染 |

差异热图显示：AI 天空的作用范围**全部落在天空内，边界贴着山脊和树冠，
是不规则的自然边缘**；而径向版在坡顶边缘有一圈圆钝的溢出。

### 错二：前景暗框用径向反相

径向 + `MaskInverted` 做暗框，四个角会出现圆弧状的压暗痕迹。
正确做法是线性 `zero(y=0.56) → full(y=1.10)`，让暗部从上到下连续渐隐。

### 错三：因为「以前踩过坑」而完全绕开 AI 蒙版

这是最要命的一条。曾经把「导出卡死」归因为「AI 天空吃爆内存」，
于是所有方案都绕开 AI 天空，改用径向手画——结果每一版的天空边界都不干净。

**真实原因是导出时弹出的「推荐 AI 更新」对话框**，和 AI 天空本身无关。
一个弹窗让我放弃了整个工具集，代价是几十层手画蒙版的精度损失。

## AI 天空的正确用法

### 写入结构

```json
{
  "What": "Mask/Image",
  "MaskSubType": 2,
  "MaskVersion": 1,
  "MaskName": "Sky 1",
  "MaskActive": true,
  "MaskValue": 1.0,
  "MaskInverted": false,
  "MaskBlendMode": 0.0,
  "MaskID": "<uuid>",
  "MaskSyncID": "<uuid>"
}
```

`MaskSubType` 取值：

| 值 | 类型 | `MaskName` 写法 |
| --- | --- | --- |
| **1** | **主体（Subject）** | `主体 1` |
| 2 | 天空（Sky） | `Sky 1` |
| 3 | 背景（Background） | — |

不需要 `MaskDigest`，Lightroom 自己算位图。48MP 照片也能正常处理。

反选（作用于非天空）只需 `MaskInverted: true`。

### 导出：用安全包装器，别直接调 export

带 AI 蒙版的照片导出时 LR 必弹「推荐 AI 更新」，阻塞插件循环。
**不要每次都靠手点，也别靠守护进程碰运气**——用包装器：

```bash
python scripts/lr_export_safe.py --path "<照片>" --dest out --long-edge 2400
```

它做三件事：导出前把 LR 首选项 `AIUpdateWarning_shouldUpdateAffectedPhotos`
置 false（实时生效、不用重启）→ 导出 → 失败则自动点框重试一次。

### 根治的原理

那个弹框的总开关在 LR 首选项里：

```
%APPDATA%\Adobe\Lightroom\Preferences\Lightroom Classic CC 7 Preferences.agprefs
    AIUpdateWarning_shouldUpdateAffectedPhotos = true   ← 改成 false
```

文本格式，安全字符串替换即可。也可以单独跑：

```bash
python scripts/fix_ai_dialog.py --status    # 看当前值
python scripts/fix_ai_dialog.py             # 关闭警告
python scripts/fix_ai_dialog.py --restore   # 恢复
```

**实测要点：**

1. 改完立即生效，不用重启 LR（改完 5 秒后导出，5.3 秒出图、无弹框）
2. 但 LR 会在约 2 分钟内把文件写回 `true`——磁盘上变回去了，**内存里仍然生效**，
   所以一个会话内一直有效
3. **LR 重启后失效**，要重跑；这也是包装器每次导出都过一遍的原因
4. 副作用已验证：跳过更新的导出与更新后的导出，同尺寸像素平均差 1.3、最大 15，
   差异是均匀细碎噪点、**没有任何形状或边界**，AI 蒙版的识别效果完整保留

### 卡住了怎么办（关键）

**第一反应：去点「导出」按钮。不是怀疑桥接坏了，不是重启 Lightroom。**

症状识别：

```
heartbeat.txt 时间戳不再更新（停了几分钟）
inbox/ 里 .cmd 文件越积越多
导出目录是空的
但任务管理器里 Lightroom 的「响应」状态是"正在运行"
```

处置：

```bash
python scripts/lr_unstick.py           # 自动找对话框并点「导出」
python scripts/lr_unstick.py --list    # 只看不点
```

手工办法：枚举 LR 的可见窗口，找 `TITLE=[推荐 AI 更新]`，
点它子窗口里文字为 `导出` 的 Button（`SendMessage(hwnd, 0x00F5, 0, 0)`）。

**绝对不能点「更新受影响的照片」**——那会重算所有 AI 蒙版，几十分钟起步，
而且会改变照片外观。

点完之后验证：心跳恢复、inbox 清空、导出目录出现文件。

### 卡住时不要做的事

- 不要重启 Lightroom（会丢掉用户的选区，也丢未保存的编辑）
- 不要以为是照片太大/内存不足（这个误判过一次）
- 不要把卡住的 `.cmd` 当成"写入失败"重新发一遍（会重复执行）

**如果 inbox 里积压着会覆盖数据的命令（比如整棵蒙版树），先把那条删掉再解卡。**

## AI 主体：生态/动物片的主力工具

`MaskSubType=1` 是「选择主体」。**对细长盘曲的动物形态同样精准**。

实测：一条翠绿色、盘成三折的蛇（ZTY_6191），AI 主体蒙版把头部、颈部、
每一段盘曲、尾部全部选中，边界贴着鳞片轮廓走，苔藓一点没误选。
拿 `MaskInverted` 反选就得到干净的背景。

**因此生态片的标准做法是三层：**

```
层1  AI 主体          蛇/虫/鸟本身：+0.05~0.15 EV、clarity +12~15、texture +10、sat +8~
层2  AI 主体 + 反选    背景整体压暗退后：−0.12~0.18 EV、sat −10~14、temp −4
层3  几何蒙版          主体内部的受光/背光面，做体积
```

**为什么生态片不能只提亮主体**：主体和背景常常是同一色系（绿蛇趴在绿苔藓上、
褐色虫子趴在枯叶上），只靠亮度分离会显得「贴上去」。必须同时做两件事：

1. **拉开亮度**：主体提、背景压
2. **拉开色相**：主体加暖/加饱和，背景降温/降饱和

实测一张绿蛇片：主体 93.5 / 背景 49.2（对比 1.90）→ 主体 101.2 / 背景 48.2（对比 2.10），
同时主体偏黄绿、背景偏深绿，主次才立住。

**注意**：主体本来就已经比背景亮时，不要再大幅提亮主体（会发荧光、塑料感）。
那张蛇片第一版给了 +0.15 EV 和 sat +12，蛇颈一片发亮像打了灯；降到 +0.06 / +0.08 才自然。

## 布尔运算：相交 / 相减 / 排除（SDK 完全可写）

**这是本 skill 最重要的一条技术结论，之前写错过一次，已用实测推翻。**

LR 界面里蒙版支持「添加 / 减去 / 相交」。SDK 通过 `MaskBlendMode` 控制，
**值域只有两个有效值**：

| 值 | 含义 | 是否被保留 |
| --- | --- | --- |
| **0** | 添加（Add） | ✓ |
| **1** | **减去（Subtract）** | ✓ |
| 2 / 3 / 4 | 无效 | ✗ 被 Lightroom 强制归零 |

实测方法：一层挂两个 `CorrectionMasks`，第二蒙版分别写 0/1/2/3，写回后 dump：

```
写入 1 → 读回 1.0    ✓ 保留
写入 2 → 读回 0.0    ✗ 归零
写入 3 → 读回 0.0    ✗ 归零
```

### 没有「相交」值，但可以算出来

集合运算恒等式：

```
A ∩ B  =  A − (¬B)
```

所以「相交」= **`MaskBlendMode=1`（减去）+ 第二蒙版 `MaskInverted=true`（反相）**。
两个字段都能写入成功。

### 三种配方

```json
// ① 相交：AI 主体 ∩ 头部框  → 只作用于「蛇头范围内的蛇」，背景零污染
"CorrectionMasks": {
  "1": {"What": "Mask/Image", "MaskSubType": 1, "MaskName": "主体 1",
        "MaskBlendMode": 0.0, "MaskInverted": false},
  "2": {"What": "Mask/CircularGradient", "MaskName": "径向渐变 2",
        "MaskBlendMode": 1.0, "MaskInverted": true,
        "Left": 0.448, "Top": 0.428, "Right": 0.552, "Bottom": 0.522,
        "Feather": 45.0, "Midpoint": 50.0, "Roundness": 0.0, "Angle": 0.0}
}

// ② 相减：AI 主体 − 头部框  → 只作用于「蛇头以外的身体」
"MaskInverted": false   ← 只改这一个

// ③ 排除：AI 主体 − 背景亮斑 → 主体统一处理，但躲开某处
//    同上，第二蒙版换成要躲开的区域
```

### 实测验证（ZTY_6191 绿蛇，层内 EV +0.40 便于观察）

**配方②（相减，`MaskInverted=false`）** —— 应该是"身体不含头"：

| 区域 | 平均差异 |
| --- | --- |
| 蛇头（框内） | **2.5**（没变） |
| 蛇颈 | 13.2 |
| 蛇身中段 | 9.1 |
| 蛇尾 | **14.4** |
| 苔藓 · 背景 | 2.3 · 0.0 |

**配方①（相交，`MaskInverted=true`）** —— 应该是"只有头"：

| 区域 | 平均差异 |
| --- | --- |
| 蛇头（框内） | **8.4** |
| 蛇头中心 | **11.4** |
| 蛇颈 | 1.9（羽化过渡） |
| 蛇身中段 · 蛇尾 | **0.0 · 0.0** |
| **苔藓（紧邻头）· 背景森林** | **0.0 · 0.0** |

差异热图确认：红色只覆盖蛇头，**边界贴着蛇头轮廓走，不是圆形**，
苔藓和背景一个像素都没动。

### 这条解决了什么问题

**几何蒙版不认物体边界。** 一个径向框打在蛇头上，框内的苔藓会一起被提亮——
用户一眼就看出来「你这么一打，它直接背景也亮了」。

以前的做法是"缩小框、加 Feather 淡化污染"，本质是妥协。
现在用 `主体 ∩ 框`，**框只负责限定范围，主体负责限定边界**，污染归零。

### 通用做法

凡是「只处理主体的一部分」的需求，一律走布尔，不许再用纯几何框：

| 需求 | 配方 |
| --- | --- |
| 只提主体头部 | 主体 ∩ 头部框 |
| 只处理主体下侧（接触阴影不碰到背景） | 主体 ∩ 下侧带 |
| 主体整体，但躲开某块亮斑 | 主体 − 亮斑 |
| 只处理背景某一块（不碰主体） | 背景反选 ∩ 该块 |
| 天空局部暖色（不碰山脊） | AI 天空 ∩ 局部框 |

### 怎么在脚本里写

`scripts/mask_append.py` 的 spec 增加 `intersect` 字段：

```json
{"name": "蛇头", "kind": "radial", "lt": [0.448,0.428], "rb": [0.552,0.522],
 "intersect": "subject", "ev": 0.12, "clarity": 12}
```

`intersect` 取值：`"subject"`（主体）/ `"sky"`（天空）/ `"background"`（背景），
或直接给 `MaskSubType` 数字。脚本会自动生成两个蒙版 + 正确的 BlendMode。

### 我在这里犯过的错（留档）

第一次测的是 `MaskBlendMode=3`，读回 0，于是写进 skill「SDK 做不到嵌套，只能叠加，
框内背景会被污染」，并用这个结论给用户交了两次稿。
用户质疑「背景也亮了」时，我还用"污染可接受"来解释。

**真实原因只是我试错的值不对。** 教训：**判断"某功能不支持"之前，
把值域 0/1/2/3 全试一遍，或者用集合恒等式绕过去。**
一个没试到的值，代价是连续几张图的精度。

## 主体「加亮」的陷阱（实测）

一张绿蛇片，蛇头区域 117、**颈部 145**。我按直觉给颈顶加了 +0.12 EV：

| 区域 | 加之前 | 加之后 | 变化 |
| --- | --- | --- | --- |
| 眼睛 | 114.0 | 125.4 | **+11.4 有效** |
| 蛇头 | 114.5 | 117.3 | +2.8 几乎没用 |
| 颈顶 | 145.3 | 146.7 | **+1.4 完全无效** |

原因：**颈顶 145 已经接近高光区，再加 EV 会被高光压缩吃掉**，出不来。

更要命的是——**颈部比头部亮 28**。所以「头不突出」根本不是头不够亮，
是脖子太亮。

### 正确诊断顺序

主体不突出时，先量一遍主体各部位的亮度，找出**谁最亮**：

- 最亮的地方在主体核心（头/眼）→ 提亮有效，继续
- 最亮的地方在主体边缘（颈/背/尾）→ **压暗那个地方**，不要去提头

实测修正：颈部 −0.22 EV 从 145 压到 130，同时头顶 +0.12、下巴 −0.16，
头部才真正成为焦点。

### 头部塑形：不是一个蒙版提亮

```
头顶受光    +0.10 ~ +0.14   Feather 35–40（只包头顶面）
下巴阴影    −0.14 ~ −0.18   Feather 30–35（只包下颚）
眼睛虹膜    +0.20 ~ +0.25   clarity 25–30，框宽约画面 3%
```

三个小框，各管一件事。合起来头就有球感；
用一个「头部整体提亮」永远出不来，因为那是把球拍平。

## 组合用法

一个层只能挂一个蒙版，但可以多开几层实现复杂分区：

```
层A  AI 天空          整片天空压暗
层B  线性（地平线）    天空下缘加暖
层C  径向（云团）      单朵云提亮
层D  AI 天空 + 反选    地面整体微调
```

A 和 B 配合，就得到「天空整体压暗 + 下缘暖色」的效果，
这是单个蒙版做不到的，也是为什么要分层而不是纠结一种蒙版。

## 检查清单

每铺完一层，问四句：

1. 这个效果是「整片的」还是「局部的」？整片没用 AI 就是错
2. 边界放大到 100% 看，能不能看出形状？能看出圆形就是选错了类型
3. 有没有影响到不该动的区域？对比差异图确认
4. 如果是 AI 蒙版，导出前挂了 autodialog 吗？
